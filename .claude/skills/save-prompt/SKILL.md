# save-prompt:プロンプトと結果の記録・push

このセッションでユーザーが送ったプロンプトと、その結果として行った作業内容を Markdown で記録し、リポジトリの変更をすべてコミットして main に push する。

## 手順

### 1. ファイル名を決める

1. 日付を取得する:`date +%y%m%d`(例:`260901`)
2. 連番を決める:`docs/prompt/` 内に同じ日付で始まるファイルが
   - なければ `01`
   - あれば既存の最大連番 + 1(ゼロ埋め2桁)
3. 題名を決める:プロンプトの内容を表す短い日本語(10〜20文字程度)。ファイル名に使えない文字(`/` など)は避ける。
4. ファイル名:`YYMMDD-連番-題名.md`(例:`260901-01-webアプリ作成計画.md`)

`docs/prompt/` が存在しなければ作成する。

### 2. ファイル内容を書く

以下のテンプレートで書く。

```markdown
# 題名

日付:YYYY-MM-DD

## プロンプト本文

> (ユーザーが送ったプロンプトを原文のまま引用する。複数ターンにわたる場合は対象ターンをすべて含める。添付ファイルがあった場合はファイル名を列挙する)

## 結果の内容

(このプロンプトに対して行った作業の要約:
- 作成・変更したファイルの一覧と各ファイルの概要
- 下した主要な判断・決定事項
- 未対応の項目や次のアクションがあればそれも書く)
```

- プロンプト本文は要約せず**原文のまま**残す。
- 結果の内容は、後から読んだ人が「何をどこまでやったか」を把握できる粒度で書く。

### 3. git add・コミット・push

```bash
git add -A
git commit -m "docs: プロンプト記録を追加(YYMMDD-連番-題名)ほか"
git push -u origin main
```

- コミットメッセージは実際の変更内容に合わせて調整してよい(プロンプト記録以外の変更も一緒にコミットされるため)。
- push が失敗した場合はネットワークエラーなら 2s→4s→8s→16s の指数バックオフで最大4回リトライする。
- セッションの制約で main への push が禁止されている場合(作業ブランチが指定されているリモート環境など)は、指定された作業ブランチに push し、その旨をユーザーに報告する。

### 4. 完了報告

保存したファイルパス、コミットハッシュ、push 先ブランチをユーザーに報告する。
