# まもログ Webアプリ開発計画

作成日:2026-09-01
ステータス:承認待ちドラフト

> **働いた記録が、あなたを守る。**

本計画は `docs/specs/` の4文書(プロダクト企画書・アルゴリズム調査・実装仕様書・ブランディング方針)をもとに、Webアプリ「まもログ」のMVPを開発するための計画である。

---

## 1. プロダクト概要

毎日「出勤」「退勤」を押すだけで勤務を記録し、以下を支援する労働リスク管理アプリ。

1. 記録する
2. 異常に気づく
3. 証拠を守る
4. 相談先を知る
5. 相談用資料を出力する

企業を「ブラック企業」と法的に断定することはせず、本人の勤務実態から労働上のリスクを可視化する(詳細は `docs/specs/implementation-spec.md` §2 の最重要原則を参照)。

## 2. 技術方針

### 2.1 基本方針:ローカルファースト PWA

企画書 §14 の「会社に見られたくないアプリ」「原則ローカル保存」「クラウド同期は明示的なオプトイン」という要件から、**MVPはサーバーを持たないローカルファーストのPWA**とする。

- 全データはブラウザの IndexedDB に保存(サーバー送信なし)
- アカウント登録不要・アクセス解析なし
- ホーム画面に追加してアプリのように利用可能(PWA)
- JSONエクスポート/インポートでバックアップ・機種変更に対応
- 静的ホスティング(GitHub Pages / Cloudflare Pages / Vercel)で配信可能

### 2.2 技術スタック(推奨)

| 領域 | 選定 | 理由 |
|---|---|---|
| ビルド | Vite + React + TypeScript | 軽量・静的出力・学習資料が豊富 |
| データ保存 | IndexedDB(Dexie.js) | 構造化データ・容量・クエリ性能 |
| 状態管理 | React hooks + Dexie live query | MVP規模では追加ライブラリ不要 |
| スタイル | Tailwind CSS | 画面数が多くても統一しやすい |
| PWA | vite-plugin-pwa | オフライン動作・ホーム画面追加 |
| ルーティング | React Router | 画面遷移(§5参照) |
| PDF出力 | ブラウザ印刷(print CSS)→ 将来 pdf-lib 等 | MVPは印刷ベースで十分 |
| CSV出力 | 自前実装(Blob ダウンロード) | 依存を増やさない |
| テスト | Vitest(スコアリングロジック中心) | 判定ロジックの正しさが製品価値 |

### 2.3 スコアリングルールの外部化

実装仕様書 §43–46 のとおり、判定ロジックの閾値・点数・警告文・出典URLは **`src/scoring/rules/*.json`** として外部化し、コードはルール評価エンジンに徹する。法改正時にルールファイルの更新だけで対応できる設計にする。

すべてのルールに `rule_id / source_url / effective_from / legal_claim: false` 等のメタデータを持たせ、「なぜこの警告が出たのか」画面(§47)から参照する。

## 3. データモデル(概要)

実装仕様書 §3–4 に基づく主要テーブル(Dexie):

- `profile` — 雇用形態、所定勤務時間、休憩、週勤務日数、固定残業代、業種特例、勤務制度
- `workdays` — work_date, clock_in, clock_out, break_minutes, home_work_minutes, pre/post_shift_work_minutes, holiday_work, night_work_minutes, record_source
- `troubles` — 「今日困ったこと」チェック(日別)
- `incidents` — 出来事メモ(日時・場所・相手・発言・目撃者・証拠有無・カテゴリ・severity)
- `monthly_inputs` — 会社勤怠時間・給与明細残業時間・残業申告不可回数(月別)
- `audit_log` — 記録の修正履歴(内部保持。相談用PDFに出力可能)
- `settings` — アプリロック(PIN)、表示設定、ruleset_version

欠損値は0として扱わず「判定材料不足」と表示する(§39)。各スコアにデータ信頼度(HIGH/MEDIUM/LOW)を付ける(§38)。

## 4. スコアリング実装(実装仕様書準拠)

| カテゴリ | 配点 | 主な入力 |
|---|---:|---|
| A. 長時間労働・過重労働 | 30 | 月間時間外・連勤・12h超日・深夜勤務 |
| B. 未払い・勤務記録差異 | 25 | 自己記録と勤怠/給与明細の差、申告不可回数 |
| C. ハラスメント | 20 | 出来事の severity × 頻度(パワハラ6類型+セクハラ等) |
| D. 休憩・休日・休暇 | 15 | 休憩不足日数(労基法34条基準)、連勤、有休妨害 |
| E. 雇用上の圧力・退職妨害 | 10 | チェック項目 |

- 総合レベル:LOW / CAUTION / REVIEW / CONSULT / HIGH(§28)
- **レッドフラッグは総合点と独立に判定**し、critical 時は最上位警告を表示(§30)
- 断定表現の禁止(「違法です」「未払いです」等)を警告文テンプレートで担保(§2.1, §15)
- 業種特例・変形労働時間制等は注意表示のみで自動違法判定しない(§42)

## 5. 画面構成(MVP)

企画書 §12 に基づく13画面をルーティングに落とす。

1. `/onboarding` — オンボーディング(思想説明・免責)
2. `/setup` — 勤務条件登録
3. `/` — ホーム(出勤/退勤ボタン+今月のリスク概要)
4. `/day/:date` — 今日の勤務確認・修正
5. (退勤フロー内)休憩+今日困ったことチェック
6. `/incident/new` — 出来事詳細記録
7. `/calendar` — カレンダー
8. `/report/:month` — 月次レポート
9. `/risk` — ブラック度・各リスク詳細+「なぜ?」画面
10. `/consult` — 相談先(問題種別ルーティング、公的/民間の区分)
11. `/evidence` — 証拠を守る読み物
12. `/settings` — 設定・データ管理(アプリロック、削除)
13. `/export` — データ出力(CSV / 相談用PDF / JSONバックアップ)

UX原則:通常日は2タップ(出勤・退勤)で完了。メイン画面で長文を読ませない。

## 6. 開発スプリント計画

実装仕様書 §50 の推奨開発順に準拠し、各スプリントで動くものを積み上げる。

| Sprint | 内容 | 主な成果物 |
|---|---|---|
| 0 | プロジェクト基盤 | Vite+React+TS+Tailwind+PWA 雛形、Dexie スキーマ、CI(lint/test) |
| 1 | 勤務記録 | 出勤/退勤/休憩入力、日別修正、修正履歴 |
| 2 | 月次集計 | 在社時間・実勤務時間・推定時間外・連勤・カレンダー |
| 3 | 長時間労働・休憩スコア | ルールエンジン+A/Dスコア、警告文、レッドフラッグ(RF_LONG_*) |
| 4 | 出来事記録・ハラスメント | 困ったことチェック、出来事メモ、Cスコア、RF_HAR_* |
| 5 | 勤務記録差異 | 会社勤怠・給与明細入力、Bスコア、信頼度表示 |
| 6 | 相談ルーティング | 相談先画面、スコア条件による優先表示、E スコア |
| 7 | 出力 | 月次レポート、CSV、相談用PDF(印刷CSS)、JSONバックアップ |
| 8 | 証拠保存コンテンツ | 「証拠を守る」読み物(統一形式)、オンボーディング仕上げ |

各スプリント完了時に GitHub Pages 等へデプロイし、実機(スマホ)で確認する。

## 7. MVPでやらないこと(スコープ外)

- 常時GPS取得・Google Maps 自動連携(読み物での紹介のみ)
- 給与明細OCR
- AIによる法的判定
- 企業名ランキング・口コミ・SNS機能
- クラウド同期・アカウント機能

---

## 8. プライバシー・セキュリティ設計

- データはローカルのみ。外部送信ゼロをMVPの明確な売りにする
- アプリロック(PIN。将来 WebAuthn 生体認証)
- 通知は使わない(通知本文へのセンシティブ情報表示問題を回避)
- 設定画面からワンタップで全データ削除
- 会社支給端末での利用に関する注意をオンボーディングに明記
- ページタイトル・favicon は「まもログ」のみで用途が露骨に分からないようにする

---

## 9. リスクと対応

| リスク | 対応 |
|---|---|
| 断定表現による法的リスク | 警告文をテンプレート化しレビュー可能に。`legal_claim: false` を全ルールに明示 |
| スコア閾値の妥当性 | 出典URL付きルールJSON。公開前に弁護士・社労士レビュー(仕様書§54) |
| ブラウザデータ消失 | JSONバックアップの定期リマインド、エクスポート導線を目立たせる |
| 法改正 | ruleset_version による外部ルール更新設計 |
